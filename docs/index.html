How the aliases were resolved

The bg, text, icon, and border layers store their value as a Figma VARIABLE_ALIAS — for example { "id": "VariableID:75:117", "type": "VARIABLE_ALIAS" } — and the export does not include the table those ids point at. The referenced ids form one contiguous run, 75:117 through 75:159, which is exactly 43 slots, and primitive.* contains exactly 43 colours. Laying the primitive ramps into that run in the order neutral, brown, amber, blue, green, red, yellow makes every semantic name land on a sensible shade: text.primary resolves to neutral.600, text.disabled to neutral.300, and each status family lands on its own hue with a clean tint → solid → hover progression (bg.error-primary → red.100, its hover → red.200, bg.error-secondary → red.300, its hover → red.400). The nine slots no semantic token references are the entire amber ramp plus four odd shades, which is what an unused legacy ramp looks like. This ordering is inferred, not stated in the file — if you can export the variable table from Figma, check it against ALIAS_RAMP_ORDER in build.mjs.
